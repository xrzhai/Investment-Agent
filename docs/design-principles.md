# Design Principles

Investment-Agent 的架构判断与设计取舍。

---

## 1. 工具质量是 Harness 的护城河

**来源：** 读李博杰《深入理解AI Agent》Ch1 "模型即Agent" 讨论（2026-07-24）

### 核心判断

Agent 模型通过 RL 后训练持续内化的是"工具调用的决策策略"（何时调用、调哪个、错误后怎么处理），而非工具的执行机制本身。

这意味着一个分工边界会越来越清晰：

| 属于 Harness（你的代码） | 属于模型（会被吃掉） |
|---|---|
| 工具的实现代码 | 编排逻辑（先 A 后 B） |
| 工具的 schema（name/description/parameters） | 错误重试策略 |
| 安全约束（权限、速率限制、敏感操作确认） | ReAct / Plan-then-Execute 等思考框架提示 |
| 状态管理（会话、记忆、持久化） | 工具调用格式的规约理解 |

### 实操含义

在 Investment-Agent 中，应该把精力集中在这几件事上：

- **工具实现质量**：功能正确、边界条件覆盖、返回结果规整
- **工具描述精度**：名称、说明、参数 schema 写得越清楚，模型犯错越少
- **工具返回格式**：结构化的、机器可读的返回，比自然语言段落好一万倍
- **安全护栏**：哪些操作需要确认、哪些数据不能暴露、哪些金额不能超

而以下这些不用过度工程化：

- 编排逻辑（"先刷新价格再算持仓"——模型自己会判断顺序）
- 错误重试循环（模型拿到错误返回自己能决定要不要重试）
- 思考框架提示词（模型越来越不需要你教它"一步一步思考"）

### 一句话

**工具实现和工具描述精度，是你永远在 Harness 层的护城河——模型帮不了你，这里的投入不会贬值。**
