# Harness 架构说明

## 核心关系

```text
外部 Agent
   |
   | 直接阅读、搜索、理解并创作
   v
Markdown 知识与历史 -------------------- current.md 版本指针
research / portfolio 记录                冻结的 facts / sources
   |
   +----------------- 决策 ----------------+
                                         |
                                         v
                               Portfolio 确定性工具
                               SQLite / 事务 / 计算
```

仓库不生成或裁剪 Agent 的上下文。摘要、索引、tags 和 workflows 只是帮助 Agent 找到
材料；Agent 可以继续打开任何与问题有关的原文。

## 两种数据形态

Research 以 Markdown 为主，因为长篇语境、矛盾、推断和未完成想法需要自然语言。
公司当前正文只由 `current.md` 一处指出。部分公司保留冻结的 `facts.jsonl`、`sources.json`，可直接阅读；研究侧不再维护结构化写入代码。

Portfolio 使用 SQLite，因为持仓、现金、成交、期权和报价需要原子性、幂等和可查询性。
代码只保障这些确定性问题，不评价研究内容。

## 稳定组件

- 用户研究思想与基本原则；
- Markdown 研究、历史记录和导航索引；
- `current.md` 版本指针与对它的只读检查；
- 组合事件、报价和状态存储；
- 组合计算、事务一致性和只读诊断。

## 明确不做

- 内置 LLM client 或 Agent 编排循环；
- Context Router、字符预算或自动截断；
- 用程序决定 Agent 可以阅读哪些研究资料；
- 固定 thesis 大纲、研究评分或发布门禁；
- 自动交易；
- 把行情供应商输出自动升级为已核验研究事实。

## 上下文使用

- 先理解问题，再用 `rg`、链接、日期、symbol 和 tags 寻找材料；
- 发现重要线索时可以扩大范围、跨公司比较、追溯旧版本或核验 source docs；
- 上下文很大时分批阅读并保留工作摘要，而不是截断原文；
- 需要引用或改变当前判断时，回到原始来源核验；
- 历史观点可以启发研究，但要区分“当时怎么想”和“现在能证明什么”。

无目的地递归读取整个大型目录通常效率不高，但这只是搜索建议，不是禁令。

入口与 Research / Portfolio 的阅读顺序见根目录 `AGENTS.md`。
