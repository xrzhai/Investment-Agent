# Research 提示

这是一组可选问题，不是流程、模板或最低覆盖要求。

## 从问题和上下文出发

先理解用户真正想知道什么，再阅读 `config/research-context.md` 以及仓库中与问题有关的
thesis、笔记、review、其他公司案例和来源。可以从 summary、index、tags 或 `rg` 开始，
也可以直接打开用户点名的原文。

研究中出现新线索时继续追踪，不需要因为最初任务像“事件更新”或“快速扫描”就停下。
同一次研究可以自然地包含事实核验、历史回顾、跨案例泛化、商业模式重构和估值更新。

## 可能有帮助的问题

- 客户是谁，付钱买的是什么变化？
- 公司如何从价值池中取值，这种“税基”为什么可能持续？
- 护城河来自结构、组织习惯、生态、规模，还是暂时的供给稀缺？
- 哪些财务和经营指标真正代理了我们关心的商业问题？
- 最强的反方解释是什么，什么事实会推翻当前理解？
- 当前价格隐含了怎样的增长、利润率、资本回报或优势持续期？
- 历史记录中有没有可以迁移的新 idea、反例或尚未完成的问题？

无关的问题可以跳过；更重要但未列出的问题应主动补充。

## 使用证据

重要事实尽量保留来源、日期/期间和定位。区分 reported fact、management guidance、
consensus、assumption 和 inference。旧 thesis、笔记和 prior Agent output 可以帮助理解
思考演化，但不单独证明当前事实。

`facts.jsonl`、`sources.json`、status 和 tags 都是可选辅助。只有在未来检索、追踪或
核验确实受益时才更新，不为了形式完整而制造记录。

## 留下成果

短期探索可以直接回答。值得延续的内容可以写成自然 Markdown、更新当前 thesis、添加
idea note 或记录新来源。正式 thesis 更新通常保留新版本和 `current.md` 指针，但文章
结构和长度完全由 Agent 决定。

估值属于 Research。个人成本、盈亏和仓位可以在用户讨论组合时加入，但先把商业判断
与组合约束分别说清楚。
