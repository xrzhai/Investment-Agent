# Agent 数据 / 工作流 / 安全层候选框架 — 2026-05-31

**状态：** working seed  
**用途：** 从“token 成本 / Agent 循环 / SaaS 计费模式变化”的讨论出发，为组合寻找除 NVDA / hyperscaler 之外的 AI beta：数据、workflow、observability、安全与执行边界。  
**口径：** 本文不是正式 coverage，不给买入价；只用于候选池和后续建仓/coverage 优先级。

---

## 0. 核心判断

模型 / API 层只给第一梯队溢价。低价值、通用型任务会被开源模型、模型路由、缓存和价格战商品化；只有同时具备 frontier intelligence、成本效率、分发入口、开发者生态或企业 workflow 重力的第一梯队，才可能把 API 卖出溢价。

Agent 时代的非模型层机会，重点不在“谁也说自己有 AI”，而在：

1. Agent 必须读写哪些数据；
2. Agent 的每一步行动在哪里留下系统记录；
3. 谁管理 Agent 能看什么、改什么、调用什么；
4. 谁监控 Agent workflow 出错、超预算、性能退化和安全事件；
5. 谁能把 usage-based 计费从人类 seat 转成机器调用量 / 数据量 / workflow 量。

压缩句：

> 从 Seat Economy 到 Loop Economy：未来软件收入不只来自多少人坐在系统前，而来自多少自动化循环依赖它、调用它、记录在它里面，并愿意为正确行动付费。

## 1. 业务层分类

### A. 数据云 / 数据库 / 搜索层

Agent 要做企业任务，首先要接触可信数据。数据层的价值来自存储、查询、治理、权限、schema、上下文质量，而不是“也接了一个模型”。

| 公司 | 角色 | Agent 逻辑 | 主要问题 |
|---|---|---|---|
| SNOW | 企业数据云 / data warehouse / data sharing | 如果企业把 structured / semi-structured 数据放在 Snowflake，Agent 查询和数据应用会带来 usage 增量 | 估值高；是否能从数据仓库扩到 AI app / governance；Databricks 私有竞争 |
| MDB | developer database / document DB | Agent app 需要 flexible data layer；开发者心智较强 | 数据库竞争激烈；云厂商托管数据库压制；增速和利润率能否兼顾 |
| ESTC | search / logging / security analytics | 非结构化搜索、日志、向量检索、observability/security 横跨多场景 | 增速较慢；更像便宜 optionality，不是最纯 AI beta |
| CFLT | real-time streaming data | Agent 需要实时数据流；事件驱动 workflow 重要 | 2026-03 已被 IBM 收购并从 Nasdaq 退市，已不是直接可买标的 |

### B. Observability / telemetry / Agent 运行监控

Agent 越多，系统越像分布式自动化黑箱。谁能看见每一步调用、延迟、成本、错误、依赖关系，谁就有可能成为 Agent runtime 的“仪表盘”。

| 公司 | 角色 | Agent 逻辑 | 主要问题 |
|---|---|---|---|
| DDOG | cloud observability / logs / APM / security | 应用、模型调用、工具调用、成本与故障追踪都会增加 telemetry 需求 | 估值很高；需要证明 AI/agent 不是只带来成本，也带来 ARPU/usage |
| DT | enterprise observability / AIOps | 更成熟企业客户、利润率较好 | 增速较慢，弹性不如 DDOG |
| ESTC | logs/search/security analytics | 同时横跨数据搜索与 observability | 叙事纯度较低，但估值更低 |

### C. 安全 / 身份 / 权限边界

Agent 的本质是“能行动的软件主体”。它一旦能读文件、发邮件、改 CRM、跑代码、下单、付款，安全问题会从“人登录系统”升级到“机器身份和权限链”。

| 公司 | 角色 | Agent 逻辑 | 主要问题 |
|---|---|---|---|
| CRWD | endpoint + cloud + identity + security data platform | Agent 越多、端点和身份越复杂，Falcon 数据平台和检测响应价值提升 | 估值极高；需验证平台化能否继续扩 module |
| PANW | network/cloud/security platform；已收购 CyberArk | 平台化安全 + identity security，可能吃到 Agent 权限边界整合 | 大而全、并购整合复杂；增长相对更成熟 |
| ZS | zero trust / secure access | Agent 和人都需要通过安全访问层连接企业资源 | 竞争强，增速/利润/估值需要平衡 |
| OKTA | identity / access management | Agent 身份和授权体系可能强化 IAM 价值 | 增速相对低；是否能从人类身份扩到 machine/agent identity |
| FTNT | network security / firewall | 更成熟、利润率更好，偏安全 beta | AI/Agent 叙事纯度低，但现金流质量更稳 |
| S | endpoint security challenger | 小盘弹性 | 亏损、竞争压力大，更偏交易/主题池 |
| CYBR | privileged access / identity security | Agent 时代 PAM 逻辑很强 | 2026-02 已被 PANW 收购，单独股票不再是主要表达 |

### D. Workflow / enterprise system of record

Agent 最后不是停在模型里，而是进入企业系统：CRM、ITSM、客服、项目管理、代码仓库、销售与营销系统。系统记录和权限边界越强，越可能从 seat 转向 workflow / usage。

| 公司 | 角色 | Agent 逻辑 | 主要问题 |
|---|---|---|---|
| NOW | ITSM / workflow / enterprise automation | 企业内部流程、审批、IT/HR/客服任务非常适合 Agent 化 | 估值不低，但比高弹性 SaaS 更稳；需验证 AI monetization |
| CRM | CRM + Data Cloud + Agentforce | 销售/客服/营销 workflow 原生适合 Agent；数据和客户记录深 | 增速较低；席位制受冲击，需要看 usage / Agentforce 是否补上 |
| TEAM | Jira/Confluence/dev collaboration | 软件团队 workflow 和知识库可被 Agent 深度调用 | seat 模式受冲击；但系统记录强 |
| GTLB | DevSecOps platform | coding agent / CI/CD / code review / security workflow 的系统记录 | 小盘、竞争强、盈利能力需验证 |
| HUBS | SMB CRM / marketing automation | 中小企业 go-to-market Agent 化 | SMB 周期和竞争压力；AI 叙事纯度中等 |
| PLTR | ontology / AIP / enterprise decision workflow | 最像“Agent 操作系统”的公开标的之一，收入增速和利润率强 | 估值极端，不能把好业务直接等同于好价格 |

### E. Edge / runtime / connectivity + security

Agent 不一定只跑在云中心，也可能跑在边缘、浏览器、worker、企业网关和安全访问层。

| 公司 | 角色 | Agent 逻辑 | 主要问题 |
|---|---|---|---|
| NET | CDN / security / Workers / edge runtime | 如果 Agent app 需要低延迟、边缘执行、安全与开发者 runtime，Cloudflare 有独特位置 | 估值极高；仍需证明 Workers/AI 能显著改善利润和大客户 ARPU |

## 3. 候选优先级

### 如果只想拿 Agent data/workflow/security beta

更合适的不是单押 SNOW，而是小篮子：

- DDOG：Agent observability / telemetry 核心表达；
- SNOW：数据云 / usage-based 数据层表达；
- PANW 或 CRWD：安全边界表达；
- NOW 或 CRM：workflow/system-of-record 表达；
- NET：edge runtime + security 的高弹性表达；
- 可选 PLTR：AIP / ontology 表达，但估值太极端，若买只能小权重。

### 个人偏好的初筛顺序

1. **DDOG** — 最贴近“Agent 跑起来以后需要看见每一步”的需求，但估值高。
2. **SNOW** — 最贴近“数据重力 + usage pricing”，但要验证 AI usage 能否抵消传统 data warehouse 竞争。
3. **PANW / CRWD** — 安全是 Agent 行动扩张后的刚需；PANW 更平台整合，CRWD 更高弹性。
4. **NOW / CRM** — workflow/System of Record，更稳但 beta 弹性可能较低。
5. **NET** — 技术位置很美，但当前估值对执行要求极高。
6. **PLTR** — 业务叙事最顺，但价格极度反映乐观，适合观察或极小主题仓，不适合无脑 beta。

## 4. 下游需求在哪里发生：避免买到“和超大云厂商硬抢”的公司

### 4.1 先画需求路径

Agent / AI app 的下游需求不只发生在云厂商的模型 API 入口，而是沿着一条企业生产链扩散：

1. **模型调用层**：OpenAI / Anthropic / Gemini / Bedrock / Azure OpenAI / Vertex AI，云厂商和模型公司最强。
2. **应用运行层**：企业自己的 app、agent service、workflow automation、internal tool，通常跑在 AWS/Azure/GCP 或私有环境。
3. **数据与上下文层**：Snowflake / Databricks / BigQuery / S3 / databases / vector store，Agent 要拿可信上下文。
4. **系统记录与业务动作层**：ServiceNow / Salesforce / Jira / GitLab / Zendesk / ERP，Agent 真正完成任务并留下审计记录。
5. **可观测性与成本控制层**：Datadog / Dynatrace / Elastic / cloud-native monitors，监控模型调用、工具调用、服务链路、错误、延迟和成本。
6. **安全、身份与权限层**：PANW / CRWD / ZS / OKTA / CyberArk-like PAM，控制人和 Agent 能访问什么、改什么、调用什么。
7. **连接、边缘与网关层**：Cloudflare / Akamai / Fastly / API gateways，处理流量、缓存、rate limit、fallback、bot/agent 访问、安全边界。

越靠近第 1 层，越容易和云厂商 / 模型公司正面竞争；越靠近第 4-6 层，越可能成为企业“跨云、跨系统、跨模型”的中立软件供应商。

### 4.2 我们想买的不是“替代 AWS/Azure/GCP”，而是“云越多、Agent 越多，它越必要”

筛选器：

| 问题 | 喜欢 | 警惕 |
|---|---|---|
| 与云厂商关系 | 集成 AWS/Azure/GCP，把多云/混合云复杂度统一起来 | 卖一个云厂商已经有、且可被捆绑降价的同质功能 |
| 客户痛点 | 跨云、跨模型、跨 SaaS、跨内部系统的治理/审计/监控 | 单一云内部的基础资源监控、基础推理 API、基础数据库 |
| 数据来源 | 来自客户自己的应用、日志、业务记录、权限链 | 主要依赖某个模型/云平台开放接口 |
| 替代成本 | 切走会丢历史 telemetry、规则、dashboard、workflow、审计链 | 换个 provider/API wrapper 就能迁移 |
| 预算归属 | SRE / security / compliance / workflow owner，生产系统刚需 | innovation budget / AI lab 试点预算，容易被砍 |

压缩原则：

> 不买“和 hyperscaler 抢低层算力/基础服务”的小公司；优先买“站在 hyperscaler 之上，替企业管理多云、多模型、多系统复杂度”的软件供应商。

### 4.3 按这个筛选器看 DDOG 和 NET

**DDOG 更符合“中立软件供应商”。**  
Datadog 官方定位就是 multi-cloud / hybrid observability，支持 AWS、GCP、Azure、Alibaba Cloud，以及 1,000+ integrations。它不是让客户不用 AWS CloudWatch / Azure Monitor，而是在客户已经使用多云、Kubernetes、SaaS、数据库、模型 API、CI/CD 和安全工具时，做统一视图、trace、logs、APM、security signals 和 cost/latency/error 分析。

云厂商当然有竞争产品：CloudWatch、Azure Monitor、Google Cloud Operations。但 DDOG 的不可替代性来自：

- **跨云中立性**：企业不希望每个云各看一套监控。
- **应用级上下文**：真正排错通常跨 cloud infra、app code、database、queue、API、LLM call、frontend、security alert。
- **历史 telemetry / dashboard / alert rule / incident workflow 沉淀**：迁移不是换 API，而是重建运行知识。
- **Agent 特殊复杂度**：Datadog LLM Observability 已能监控 OpenAI Agents SDK、LangGraph、CrewAI 等 agentic systems 的 error、latency、cost、tools used、handoff 和 end-to-end execution。

所以 DDOG 不是完全没有云厂商竞争，但它抢的不是“低层云资源”，而是跨云生产系统的统一运行控制面。这个方向更符合我们的偏好。

**NET 一半是中立供应商，一半在进入云厂商地盘。**  
Cloudflare 的 connectivity cloud / security / CDN / WAF / DDoS / Zero Trust 很像中立供应商：企业不想被某个云绑定，Cloudflare 坐在互联网入口和安全边界上，云越多越有价值。

但 Cloudflare Workers、Workers AI、Vectorize、R2、Dynamic Workers 这些产品，确实更接近 hyperscaler 的 compute/storage/database/inference 地盘。Cloudflare AI Gateway 则比较中立：它连接 OpenAI、Anthropic、Google、Workers AI 等多个 provider，提供 analytics、logging、caching、rate limiting、retry、model fallback 和成本可见性。

因此 NET 的不可替代性要拆开：

- **更稳的部分**：global network、security edge、Zero Trust、DDoS/WAF、traffic control、AI Gateway 作为多模型控制面。
- **更冒险的部分**：Workers / edge compute / Workers AI 是否能成为大量 agent workloads 的真实运行层，而不是和 AWS Lambda / Azure Functions / GCP Cloud Run 正面抢低层 compute。

当前结论：NET 不能简单说“最正”。它的位置很美，但确实有一部分是在向 hyperscaler 地盘延伸。组合上应把 NET 当高弹性 satellite，而不是 DDOG 那种更中立的主表达。

## 5. DDOG vs NET：逻辑正不正

### DDOG：逻辑最正，但不是最便宜

DDOG 在 Agent 链条里的位置更靠近“必经的运行监控层”：

- Agentic system 天然非线性：多模型、多工具、多 step、重试、handoff、错误和成本都需要 trace。
- Datadog LLM Observability 已经直接支持 agent monitoring：监控 error rate、latency、cost，展示 agent decisions、tools used、handoff，并 trace end-to-end agent executions；支持 OpenAI Agents SDK、LangGraph、CrewAI 等框架。
- 2026 Q1 公司收入 $1.006B，+32% YoY；约 4,550 个 $100k+ ARR 客户；OCF $335M、FCF $289M；同时推出 MCP Server、Bits AI Security Agent、GPU Monitoring、Experiments GA。

判断：DDOG 的逻辑比“泛 AI SaaS”更正，因为它不依赖某个模型胜出，而依赖自动化系统复杂度上升。Agent 越多、链路越长、故障/成本/安全问题越多，observability 越像必需品。风险是估值已经把一部分胜利定价进去了，且要证明 AI telemetry 能成为实质增量，而不是现有客户预算里的替代项。

### NET：技术位置更漂亮，但商业映射更绕

NET 的逻辑不是“监控 Agent”，而是“给 agentic web 提供边缘 runtime + connectivity + security primitives”：

- Cloudflare Q1 2026 revenue $639.8M，+34% YoY；non-GAAP operating income $73.1M；current RPO +34% YoY。
- Cloudflare 2026 Agents Week 集中发布了 agentic cloud 相关能力，覆盖 compute、security、agent toolbox、platform tools；页面提到 AI Gateway、Workers AI、Agent Readiness、AI Search、Cloudflare Mesh、Dynamic Workers / Durable Objects 等方向。
- 它的位置横跨开发者 runtime、边缘网络、安全访问、AI Gateway、agent-facing web standards。

判断：NET 的技术审美和未来感很强，但投资逻辑比 DDOG 更“二阶”：需要证明大量 agent workloads 真的会跑在 Cloudflare 的边缘 / Workers / Gateway / Mesh 上，并且这能转成大客户 ARPU、利润率和 durable revenue，而不是停留在开发者热度。它更像高弹性 call option，而不是最直接的 Agent workflow 必需品。

### 对比压缩

| 问题 | DDOG | NET |
|---|---|---|
| Agent 链条位置 | 看见、监控、排错、控成本 | 承载、连接、保护、边缘执行 |
| 逻辑直接性 | 更直接：Agent 越复杂越需要 observability | 更二阶：要先证明 agentic workloads 选择 Cloudflare primitives |
| 商业模式映射 | usage / telemetry / logs / security platform | Workers / Gateway / security / traffic / edge runtime |
| 主要风险 | 估值高；AI 增量是否真实；云原生预算周期 | 估值极高；产品很多但收入归因难；边缘 agent 时代是否足够快到来 |
| 组合角色 | 主题 basket 的第一优先级 | 高弹性 satellite / call option |

当前判断更新：如果只问“逻辑是不是最正”，DDOG 比 NET 更直接；但如果只选一个、且研究目标是 AI Infra / agentic web 的空间和想象力，优先研究 NET。NET 的优势在于物理网络、互联网前门、security edge、AI Gateway 和 edge runtime option 叠加，商业模式更难但上限更高；DDOG 可作为后续对照对象，而不是本轮主研究对象。

## 6. 组合动作纪律

当前组合已经高度暴露于 AI token factory 和第一梯队平台，不缺 AI beta。若要新增 Agent 数据 / 安全 / workflow beta，建议：

1. 先用 TSM / META 小幅降权或现金流补足 CASH_USD，而不是新增 put 或强行加杠杆；
2. 初始总权重控制在 2%-4%，作为主题 basket，不作为核心仓；
3. 单名不超过 1%，除非后续建立正式 coverage；
4. 不追估值极端时刻，优先等 earnings miss、guidance 消化、AI 预算怀疑、SaaS seat 通缩恐慌等“鬼故事”；
5. 后续正式 coverage 优先顺序：DDOG → SNOW → PANW/CRWD → NOW/CRM → NET。
